Порядок проведения соревнования (озвучить во время проведения):
    1. Участники команд сдают телефоны и оставляют только 1 рабочий ноутбук на команду.
	2. Участники получают задание, скачивают необходимые файлы и приступают к выполнению.
    3. На создание рабочего решения дается 2 часа.
    4. По завершению времени (не раньше!) команды обязаны:
        - создать в корне проекта папку с названием своей команды;
        - скопировать туда файл dev.py, отредактированный согласно заданию;
        - сделать коммит и запушить его в репозиторий.
    5. Участники собираются все вместе и смотрят финальные прогоны решений.
    6. Определяется победитель по метрике Счет:
		- если итоговые метрики команд на лидирующих позициях равны, то прогон выполняется с другим SEED.

Причины дисквалификации:
    - использование сторонних ресурсов (поиск в интернете, подсказки через наушники, помощь со стороны, ИИ-агенты и т.д.);
    - нерабочий алгоритм (не запускается, падает с ошибкой, отсутствует и т.д.);
	- нарушение правил соревнования, например, изменение исходного кода проекта за пределами dev.py, и т.д.;
    - неспортивное поведение.

Инструкции для участников (выдаются в виде распечатки строго на старте!):

    - клонируйте репозиторий https://github.com/EgorAdamovsky/hakaton-2026 (еще уточню):
        + установите необходимые зависимости;
        + запустите демонстрацию main.py.

    - в 11-этажном офисном здании есть лифт на 8 человек, который вынужден справляться с большим потоком людей:
        + по утрам толпы работников хотят попасть на свои рабочие места с первого этажа;
        + в обед часть из них спускается в кафе на первом этаже или выходит погулять;
        + вечером они такой же толпой стремятся уйти домой, стекаясь со всех этажей на первый;
        + в течение дня отдельные группы могут прибывать и убывать из здания, а также перемещаться между этажами;
        + ночью возможны единичные перемещения сотрудников службы охраны и техников.

    - ваша задача - настроить поведение лифта таким образом, чтобы набрать максимальное количество очков (Счет):
        + P (суммарное количество перевезенных пассажиров) - нужно перевезти как можно больше;
        + AWT (среднее время ожидания) - сколько в среднем один человек ждет лифт, держите на минимуме;
        + ART (среднее время поездки) - длительность доставки пассажира к месту назначения, не стоит петлять;
        + L (общая длина маршрута) - эквивалентно энергопотреблению лифта, негативный показатель;
        + Счет = (1000 х P) / (AWT + ART + L) - итоговая метрика, по которой будет определен победитель.

    - для реализации алгоритма лифта подготовлена функция my_way(elevator: Elevator) в файле dev.py:
        + установите значение переменной TEAM на название вашей команды;
        + elevator - это сам лифт, его API описан ниже;
        + менять что-либо в других файлах проекта строго запрещено;
		+ my_way() содержит демонстрационный пример минимально рабочего алгоритма, ваше решение должно отличаться;
		+ замените код в теле my_way()  на свой.

    - в процессе тестирования можно менять параметры симуляции, но на финальном прогоне они будут переопределены:
        + длительность эксперимента (NUM_DAYS): 7 дней;
        + seed генератора трафика (SEED): будет сгенерирован случайным образом;
        + плотность трафика (DENS): 0.3;
        + скорость симуляции (SPEED_MULT): 64;
        + стартовое время симуляции (START_TIME): 0 часов.

    - лифт оперирует ограниченным набором информации:
        + текущий и целевой этаж, а также общее количество этажей здания;
        + текущая загруженность лифта;
        + список вызовов с различных этажей (откуда идут вызовы);
        + список целевых этажей у ожидающих людей (куда люди хотят приехать).
		
    - лифт не знает:
        + сколько сейчас времени.
		
    - лифт может:
        + поехать на указанный этаж без дополнительных остановок по пути;
        + высадить всех пассажиров, чей целевой этаж соответствует текущему;
        + пригласить на посадку любого выбранного пассажира из очереди на текущем этаже.
		
    - лифт имеет особенности:
        + остановка на этаже длится 30 секунд - не тормозите его без нужды;
        + управление доступно лишь тогда, когда лифт прибыл на целевой этаж (my_way() работает только в состоянии IDLE);
        + метрики обновляются на основе завершенных поездок, незавершенные в конце симуляции принудительно завершаются;
        + нумерация этажей начинается с 1, а не с 0!

Методы получения информации (другие уже существующие в проекте методы использовать нельзя):
    - elevator.get_current_floor() → int 												- текущий этаж лифта;
    - elevator.get_target_floor() → int 												- целевой этаж, к которому движется лифт;
    - elevator.get_passengers_count() → int 									- количество пассажиров внутри лифта;
    - elevator.get_capacity() → int 													- максимальная вместимость лифта;
    - elevator.get_building_floors() → int 											- количество этажей в здании;
    - elevator.get_passenger_destinations() → List[int] 					- список целевых этажей текущих пассажиров;
    - elevator.get_waiting_floors() → List[int] 									- список этажей, где есть ожидающие;
    - elevator.get_waiting_people(floor: int = None) → List[int] 		- список целевых этажей у ожидающих на указанном этаже;
																												+ если этаж не указан, то на текущем этаже лифта.

Методы управления (другие уже существующие в проекте методы использовать нельзя):
    - elevator.go_to_and_stop(floor: int) 											- лифт поедет на указанный этаж без остановок;
    - elevator.unload_all() 																	- высадить всех пассажиров, кому нужно выйти на текущем этаже;
    - elevator.board_passenger_by_index(index: int) → bool 		- посадить пассажира из очереди по его индексу (начиная с 0);
																												+ каждая посадка удаляет пассажира из списка ожидающих;
																												+ успешность операции возвращается в виде логического флага.
